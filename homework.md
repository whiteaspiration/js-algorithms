## Конспекты

### Git для новичков (часть 1)

- **Коммиты** - это что то вроде сохранений в играх, которые помогают зафиксировать кусок работы. Очень полезная штука
- **Ветки** - позволяют экспериментировать, по сути, в изоляции. Работаешь над своей задачей в своей ветке, не боясь случайно сделать баги в основном коде.
- **Команда 'git reflog'** - это вообще самая крутая фича! Оказывается, если даже принудительно удалить ветку со всеми файлами, git не стирает коммиты сразу, давая возможность вернуть потерянную работу обратно к жизни <ins>(в течении 30-90 дней)</ins>.
- **Git и GitHub - разные вещи** - Git работает у тебя на компе локально и хранит историю изменений, а GitHub - это просто сайт, куда ты выгружаешь проект, чтобы сохранить его в облаке или показать ревьюеру.
- **Подготовка через 'git add'** -  Ты сначала отбираешь нужные файлы в специальную зону подбора и только потом делаешь коммит — делаешь финальный «снимок».
### Git для новичков (часть 2) - командная работа

- **Конфликты слияния (Merge Conflicts)** возникают, когда два разработчика изменили одну и ту же строку в файле. Git останавливает слияние, требуя выбрать вручную какой вариант оставить
- **Правило прямой записи** любой функциональный код должен проходить через ветку и PR. Прямой пуш в <ins>*'main'*</ins> допускается только как осознанное исключение - для мелких правок документации или опечаток
- **Разница 'git fetch' & 'git pull'** первая команда только скачивает информацию об изменениях с сервера, а 'git pull' делает 'fetch' и сразу автоматически мержит их с текущей локальной веткой
- **Сравнение веток 'git diff'**: сравнивает состояние двух веток, показывая все построчные различия *(добавленные и удаленные строки)*, отличающие целевую ветку от исходной
- **Проверка состояния 'git status'** команда позволяет в любой момент показать, на какой ветке ты находишься, какие файлы изменены и что подготовлено к коммиту
